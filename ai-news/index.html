The project in one paragraph

Exact integer and rational curves on one grid. The goal is not a gallery: it is a grammar of plant-forms that becomes an ornament grammar, printed as book plates and taken to Inkscape and a glyph editor. Every curve is drawn from an equation; a curve that cannot be exact is stored as a sampled outline and says so. The operator is a craftsman, not a programmer — plain English, units on every number, and no claim without a measurement.

The truth, as of 2026-11-23

  • 393 curves in the collection. 213-ish are speed-row curves (x' = u²−v², y' = 2uv), the rest are sampled paths; the counts in 03-data.md are generated and authoritative.
  • Plates are one law: the inside of a turn is thin (capped at 0.9 / κ), the outside keeps the asked width; unedited curves sit at a 1 % gap. Red dots mark places where the outside line crosses itself (future cut points); blue marks the start, orange the end.
  • The registers are the memory: state/REGRESSIONS-int.md (faults and their tests) and state/DESIGN-int.md (settled decisions and why). LTMemory-int.md is the map.
  • The app is Astro on :4321 (Node 24). The main pages: /plates/, /review/ (the review desk), /tune/<uid> (the tuning desk), /extra-curves/ (what is missing, with drawings), /glue/ (connectors between two slopes), /class-v/ (the gothic arch), /hearts/ (the two hearts), /said/ (the operator's own messages), /jobs/ (the slow-job queue).

The working standard, in six lines

  1. Plain English; a number carries its unit and how it was measured.
  2. A rule that cannot fail a command is a wish — put the check in tests/.
  3. One exact core (curve_lab/measure.py); no second implementation of a number.
  4. A failed read is never a write; a view may hide data, never destroy it.
  5. Curves, not jagged lines: exact stations, cubic chain between them, labelled approximate.
  6. Commit per action, with the register row in the same commit.

The three words that prevent most mistakes

  • crossing — a crossing pair (two parameters through one place), never a place.
  • grid — the single integer denominator; 1/105, not "105".
  • bend — arc over chord; a plain number, no percent.

The one thing to understand about the drawings

A plate is a spine and two side curves. The side curves follow one law:

distance = min(base × (1 + strength × bow), 0.9 / κ) on the inside of a turn distance = base × (1 + strength × bow) on the outside

The inside is the side toward the centre of curvature; only it can fold. That is per station, not per side, so one rail can hug the spine while the other stays wide.

The trap in the data

  • The registry is the seed and holds the geometry; SQLite holds names, notes, stars and measurements; data/*.json are exports. Editing an export does not survive a save.
  • workbench/curve-registry.json is what the plate writer reads. The database note can drift from it (it did, by 45°, for days) — app/scripts/sync-turns.mjs fixes that.
  • A stored path is sampled, never exact. Only a speed-row curve or a named rational curve can claim exactness, and the note must say which.

Open questions

This is where your criticism earns its keep. Each item is written as the fault, what is known, and the decision it waits on.

Drawing

  1. G3 joins are not built. A cubic has 8 numbers; matching position, direction, curvature and its rate at both ends is 10 conditions. The glue sandbox is G1 and exact there. The next step is a quintic connector, and it needs each curve's curvature and curvature rate at its leg — data the records do not carry today. Question: is G3 worth the extra data, or is G1 enough?
  2. The multi-branch curves still break. c-0416 (cruciform) and c-0418 (absx-gerono) draw as fragments. Branches are now stored separately (record.branches) and the plate writer prefers them, but these two still show gaps. Fault, not a decision.
  3. A cusp's outside rail is rounded, not offset. A true offset of a cusp is discontinuous; the plate rounds the spike so the band does not shoot out. That is a drawing choice and the spec says so. Question: is a rounded cusp acceptable on a plate, or must it be cut?

Data

  1. 158 stored paths have no exact measurement. The crossing × inflection grid counts only the 262 measured curves, so some "empty" cells may be occupied. Question: is a sampled count (labelled approximate) better than no count?
  2. The 13 absent uids in c-0338–c-0364 do not exist. They are either renumbered or were never made. Decision needed: renumber, or leave the gap.
  3. The turn lives in two places (registry and database note) and drifted by 45° for days. They are synced by a script, not by construction. Question: should the note be derived from the registry, so drift is impossible?

Art

  1. The human figure is the biggest open problem: a human form at the centre of the design (the Virgin, Christ, or the two hearts). The hearts sandbox exists; nothing is stored. Decision: which emblem, at what size, and where in the composition.
  2. The plates carry working marks — red cut points, blue start, orange end, blue cusp dots. They are for judgement, not for print. Decision: when do the marks come off?

Process

  1. The launch agent loops every ten seconds on Node 22 and fails; it no longer reloads pages (the ornament writer is idempotent) but it snapshots the database each time. A one-line plist fix, outside the repository.
  2. The workhorse queue has no scheduler; the operator must start it in a third terminal. Question: should it be a LaunchAgent, and if so, who owns the lock?

Glossary

  • Curve — the line itself. Either speed rows (u, v) or a stored path.
  • Speed rows — two polynomials u(t), v(t); the position is the integral of (u²−v², 2uv). A curve in this form is exact.
  • PH curve — a curve whose speed is a Pythagorean pair; its offset is rational.
  • Stored path — a sampled outline; exact at its stations, approximate between them.
  • Grid — the one denominator that makes every station whole, written 1/G (e.g. 1/105).
  • Bend — arc length over chord length. A plain number, no percent.
  • Crossing pair — two parameters t₁ < t₂ at the same place. Three passes = three pairs. Never call this "crossings" and mean places.
  • Inflection — where the curve stops bending one way and starts bending the other.
  • Spine — the curve as the plate draws it.
  • Side curve / rail — the line beside the spine at a distance set by the law.
  • Inside / outside — the inside of a turn is the side toward the centre of curvature; only it can fold. The outside keeps the width.
  • Character rail — a side curve whose distance varies along the curve (bow, s, taper).
  • Fold — the band crossing itself because the offset exceeded the local radius.
  • Buckle — the same word the operator uses for a fold; the tuner reports it.
  • Cut point — where the outside rail crosses itself; a future place to cut the band.
  • Plate — the printed SVG: white ground, no text, two greys, the spine and its sides.
  • Class V — the gothic arch: half a Tschirnhausen trimmed, mirrored, joined at the tip.
  • Glue — a connector between two curves whose end slopes differ.
  • Wonk — the raw half a double was cut from; the doubles ("dwonkies") are the kept curves.
  • Desk — the tuning page where the four plate values are set and saved.
  • Register — state/REGRESSIONS-int.md: every fault and the test that keeps it fixed.
  • Workhorse — the queue that runs slow jobs outside the chat.

The glue connector: a cubic whose ends lie on typed slopes

app/src/lib/glue.js:51-70

export function controls(p0, p3, slope0, slope1, h0, h1) {
  const d0 = direction(slope0);
  const d1 = direction(slope1);
  if (!d0 || !d1) return null;
  const chord = Math.hypot(p3.x - p0.x, p3.y - p0.y);
  // a handle may be given as a fraction (exact) or a plain number
  const size = (value) => (value && typeof value === "object" ? fracValue(value) : Number(value));
  const H0 = chord * size(h0);
  const H1 = chord * size(h1);
  const u0 = unitDirection(slope0);
  const u1 = unitDirection(slope1);
  return [
    p0,
    { x: p0.x + H0 * u0.x, y: p0.y + H0 * u0.y },
    { x: p3.x - H1 * u1.x, y: p3.y - H1 * u1.y },
    p3,
  ];
}

The plate preset: a measured gap, not a fixed width

export function presetWidthPercent(character) {
  const strength = (Math.abs(Number(character.plus) || 0) + Math.abs(Number(character.minus) || 0)) / 2;
  return Math.round((TARGET_GAP_PERCENT / medianFactor(character.profile, strength)) * 100) / 100;
}

export const symmetricStrength = (plus, minus) =>
  (Math.abs(Number(plus) || 0) + Math.abs(Number(minus) || 0)) / 2;

The workhorse queue: one runner, a lock, one log per job

scripts/jobq.py:80-125

def run(once=False, quiet=False):
    DIR.mkdir(parents=True, exist_ok=True)
    with open(LOCK, "w") as lock:
        try:
            fcntl.flock(lock, fcntl.LOCK_EX | fcntl.LOCK_NB)
        except BlockingIOError:
            print("another runner holds the queue")
            return 1
        while True:
            data = load()
            job = next((j for j in data["jobs"] if j["status"] == "queued"), None)
            if job is None:
                if not quiet:
                    print("nothing queued")
                return 0
            job["status"] = "running"
            job["started"] = now()
            save(data)
            started = time.time()
            if not quiet:
                print(f"running {job['id']}  {job['name']}")
            log = ROOT / job["log"]
            log.parent.mkdir(parents=True, exist_ok=True)
            with open(log, "w") as out:
                out.write(f"# {job['id']} {job['name']}\n# {job['command']}\n# from {job['cwd']}\n\n")
                out.flush()
                code = subprocess.call(job["command"], shell=True, cwd=job["cwd"],
                                       stdout=out, stderr=subprocess.STDOUT)
            job["seconds"] = time.time() - started
            job["finished"] = now()
            job["status"] = "done" if code == 0 else f"failed ({code})"
            save(data)
            if not quiet:
                print(f"{job['status']}  {job['id']}  {job['seconds']:.1f}s  "
                      f"log {job['log']}")
            # the operator is often away: a job that lands must be heard, not just written
            try:
                subprocess.Popen([str(Path.home() / "bin" / "ding"), f"{job['name']}: {job['status']}"],
                                 stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
            except OSError:
                pass
            if once:
                return 0 if code == 0 else 1
