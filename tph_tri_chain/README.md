# tph_tri_chain — the discrete Pythagorean triangle chain

This directory is the home for the **discrete** route to points on the
Tschirnhausen cubic: a chain of integer right triangles stepped by exact
Pythagorean triples, not a smooth Pythagorean-hodograph curve.

## Why this name

`tph` = Tschirnhausen + Pythagorean hodograph. The suffixes disambiguate three
things that would otherwise collide in imports and prose:

| Name | Means |
|---|---|
| `tph_curve` | the smooth analytical PH curve |
| `ph_hermite` | the existing cubic Hermite / PH solver in `curve_lab/` |
| `tph_tri_chain` | **this** — the discrete triangle chain, stepped by midpoints |

The repo's existing prefix is `ph_` (`curve_lab/ph_hermite.py`,
`workbench/ph-families.html`); `tph_` is used here only to mark the
Tschirnhausen-specific variant and the discrete construction, so a bare
`tph_tri_chain` import never reads as "another PH curve module".

Alternatives considered and rejected:

- `tph_pyth_chain/` — accurate, but "pyth" reads as a vague reference rather
  than the stepping rule.
- `tph_discrete_ph/` — closest to CAD literature, but repeats `ph` twice and
  obscures the triangle construction.
- `triangles/` — too generic, and it collides with the excluded name from the
  current handoff action.

## Status

Working code for the discrete triangle chain. It is a separate method from
`ph_hermite` — do not let one stand in for the other — and nothing in
`curve_lab/` imports it yet. Nothing here is provisional: build it, run it,
use it.

## Results

`RESULTS.md` (and its HTML mirror `results.html`) carry the verified numbers.
Both are generated by `make_results.py` from `chain.py`, so they cannot
disagree. They are organised around the integer hits: the curve meets whole-number
points only at t = 0, 3, 6 … and at the waist (3, 0). Every comparison is at
twelve triangles per side, the same count for both the midpoint chain and the
chordal join.
