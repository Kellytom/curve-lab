## Highlights — what is genuinely strong

- **The exact core is real.** `curve_lab/measure.py` holds grid, bend, arc,
  inflections and closest approach in `Fraction`, and the pages quote numbers
  from it. The achievements file carries a command beside every claim, so a
  number can be re-derived instead of believed.
- **The data contract is enforced, not aspirational.** Every dataset carries a
  `format` string, one loader reads it, and `tests/test_data_audit.py` fails the
  suite when a file is on disk but not registered. I confirmed it live twice:
  `bezier-knots.json` and four hybrid files were caught within hours of appearing.
- **The visible record works.** `data/` gives a session with no SQLite the whole
  picture — 8 tables, `schema.json`, a dictionary in plain English — and
  `tests/test_data_export.py` fails when a file falls behind the database.
- **The catalogue is the deliverable taking shape.** 397 curves on one grid, the
  hybrid desk turning operator decisions (147 and counting) into registry
  records, and the naming rule ("a reader never asks which `c`") enforced from
  code to figure captions.
- **Research is honest about what it cannot prove.** Two searches (`RESEARCH-int`,
  `sin-cos-parametric-research.md`) state "no prior art found in a search", never
  "novel", name the field's terms (PH curves, offset curves, reach, crunode/
  tacnode/acnode), and mark two claims unverified on purpose.
- **The prime mover is a direction with teeth.** `PRIME-MOVER-int.md` states the
  p-triple rule, the Niven guard (a fixed triple never closes at 2π), the
  honest routes, and requires a new family to declare its driver. It changes how
  the next curve is designed, not just how it is drawn.
- **Working discipline that survives crashes.** The achievements log, the
  regressions register with its test, backup/restore, recovery scripts, and the
  mailbox protocol (one writer per file, proofs beside every Done). The rule
  "never report a narrowed result as complete" is unusual and worth keeping.

## Findings — ordered by the cost of discovering each late

### F1 · The record and the suite race each other (live red)

`test_data_export` failed inside the full run: rows were saved while the suite
ran, so the export was stale by the time the check executed. The same race will
bite every long-running job, because the desk is live and the sync is on a timer.
The fix is ordering, not tolerance: run `node scripts/export-data.mjs` at the
*start* of every gate and immediately before any commit, and let `--check` remain
strict. Cost if ignored: an intermittent red gate that trains sessions to stop
trusting green.

### F2 · `sandbox-curves` has two homes and one of them draws nothing

`workbench/sandbox-curves.json` (the `/sandbox` page's `{adders, quadrature}`)
was replaced by the `SandboxCurve` export, while the addendum's record lives at
`data/sandbox-curves.json`. Both copies exist; `/sandbox` draws no adders (the
page is guarded so it does not throw, but the section is empty). Decision
pending in the mailbox. Cost if ignored: the operator's sandbox page is blank and
nobody can tell which file is lying.

### F3 · The crossing counters are uncalibrated — and everything ranks on them

`TODO.md` (senior-dev pass, item 1) records the fault: the same curve read
**9, 4 and 1** pairs from three counters, and "540 new curves" turned out to be
flat ghosts. The three pinned numbers are `c-0262` = 9, `c-0070` = 11, and the
Chebyshev `T3 × T5` = 4. Until the counters agree, the "best curves" ranking,
the hybrid desk's solved-pair counts and the empty-cell map (77 cells of
crossings × inflections) rest on numbers that disagree with each other. This is
the highest-value fix in the file. Cost if ignored: a catalogue ranked by a
number that changes with the sampler.

### F4 · The full suite is five minutes, and three tests are the reason

`test_fleur_sets` 146 s, `test_ph_nth_sandbox2` 112 s, `test_ph_11th_sandbox2`
108 s, `test_crossings` 83 s. A session that must confirm one change waits on
all four. Split the page renderers from the logic they exercise, or cache the
expensive fixtures. Cost if ignored: sessions drift to the fast loop only, and
the slow truths stop being run.

### F5 · Generated pages can silently lose the draft-A label

`workbench/hybrid-sheets.html` and `workbench/todo.html` dropped it; the stamper
re-added it, but the fix belongs in the generators, so a rebuild cannot lose it
again. Cost if ignored: an outward page published as if final.

### F6 · 59 untracked paths, and the prime-mover page is among them

The handover block (pages, vendor library, seven scripts, specs) is uncommitted.
A crash here loses the newest part of the app. The decision is open in the
mailbox; it is an ownership question, not a technical one. Cost if ignored: real
loss, not just untidiness.

### F7 · Three commits are unpushed

Pushing awaits the operator's yes, but a red or stale remote is the backup the
project leans on (`senior-dev.md` rule and the GitHub section). Say the word and
they go. Cost if ignored: work that cannot be recovered from another machine.

### F8 · `finder.json` is 3.6 MB and is committed twice

`workbench/finder.json` and `finder.backup.json` are both 3.5 MB in git. The
audit already treats several caches as optional; this pair is a candidate.
Cost if ignored: a fat clone for data the loader can rebuild.

### F9 · Two servers, one product

`web/server.py` (stdlib, `:8003`) and the Astro app (`:4321`, Cloud Run deploy)
both serve. The docs name the app as the deliverable; the Python server is the
render MVP. Make the split explicit in the hub, or a new session tests the wrong
one. Cost if ignored: a page check that passes on a page nobody looks at.

### F10 · The dictionary must chase the record it describes

`data/README.md` is fresh today and already has to track a moving target: the
file list test keeps `DATA-int.md` and the loader in step, but nothing keeps the
*prose* dictionary in step with a new field. One test per file: "every field in
`schema.json` is named in `README.md`". Cost if ignored: the dictionary goes
quietly wrong, and the session that trusts it is the one that needed it.

## What I would do next (five actions, in order)

1. **Pin the counters (F3).** One test, three numbers, run against every
   counter; delete or rebadge the disagreeing ones. The catalogue's claims then
   rest on one definition.
2. **Settle `sandbox-curves` (F2)** — one path, one format string, the page
   reading it, and the other file deleted or redirected.
3. **Export before every gate (F1)** and re-check immediately before commit.
4. **Commit or decide the handover block (F6, F7)**, then push with the
   operator's yes.
5. **Trim the slow tests (F4)** by splitting the page renderers from the logic.

---

## One-line verdict

The rare part of this project is not the maths — it is that the maths is
*guarded*: format strings, a loader, a hash per file, a register of faults, and
a page that shows the proof. The risks are all in the seams where two systems
meet (record and suite, page and generator, session and session), and every one
of them is a decision that has already been written down and only needs to be
made.
