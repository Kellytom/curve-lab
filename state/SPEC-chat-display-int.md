# SPEC — rich chat display (a page per answer)

**Status:** proposal, parked behind the curves and the book. Nothing built beyond the two
transcript pages (`/said/`, `/deep2-said/`).

## 1 · The idea, in the operator's words

"Since you have a server running, you could use that to display plots, designs, graphics,
little interactive panes just like google chat and gemini and xai, etc. and then say in your
chat response (see full chat response in browser)."

So: the reply in the chat stays short; the full answer — figures, tables, sliders — lives at a
URL on the Astro server, and the chat carries a one-line pointer to it.

## 2 · Why it fits this project

- The server already exists (Astro, Node 24, port 4321). Nothing new has to run.
- Every figure in this project is generated by a script, so "a page per answer" is the same
  pattern as `/plates/` and `/extra-curves/`: a generator, a data file, a route.
- The chat is good at words and bad at pictures; the page is the opposite. Splitting them
  plays to both.
- A figure on a page can be looked at properly, resized, re-opened, and linked from the
  handoff — a picture pasted into a chat cannot.

## 3 · What a page per answer would be

- **One route per answer:** `/talk/<date>-<slug>/` (for example
  `/talk/2026-11-23-loop-joins/`).
- **Generated, never hand-edited:** a script or a small directory under
  `app/src/data/talk/<slug>/` holding the figures; the route renders them.
- **The chat line:** `see the full answer: http://127.0.0.1:4321/talk/<slug>/`.
- **The page holds:** the long explanation, the figures with labels, the numbers in a table,
  and — where it earns its keep — one interactive pane (a slider changing a curve, as the
  loop-end panel already does).
- **The house rules apply unchanged:** one header, one `<main id="main">`, the shared margin,
  labels inside figures, curves drawn as curves.

## 4 · The honest limits

- **It is a presentation layer.** It does not make the catalogue or the book better, which is
  why it waits.
- **Artifacts go stale.** A page that quotes a measurement must be regenerated when the
  measurement changes, or it lies. The rule: a page that prints a number either reads it from
  the data file at request time or says when it was generated.
- **Cost.** Each answer that builds a page costs a little more than a paragraph. It is worth
  it for figures, not for prose.
- **Local only.** These pages are for the operator's eye. If they ever ship, they need the
  same auth as the rest and no personal text.
- **Not a substitute for the chat.** The chat must still say the result in words; a bare link
  is not an answer.

## 5 · First measurable step (when it starts)

Take one answer that already has three figures and a table (the loop-end work is the obvious
candidate) and publish it as `/talk/2026-11-23-loop-ends/` from a generator that reads the same
files the chat used. `Proves:` the page shows the three figures from data, the chat line points
at it, and `check-pages.mjs` passes on the new route.
