# The input hub

> **draft A** — a working draft, not a final text.
How the workbench is entered, and why it is built the way it is.

## The problem

The workbench is a dozen pages, each generated by its own script, each named
after a technique: `catenary.html`, `spiral-turns.html`, `spine-sheet.html`,
`practical-curve.html`. Those names are accurate and useless. Someone who wants
"the end of a stroke to look finished" does not know to open something called
*piece-model*, and someone who wants "a line that swings" will not guess
*recovered spirals*.

A list of filenames is a filing system, not a way in.

## The shape

Three parts, each solving one of those problems.

### 1. One page, chosen by intent

`workbench/workbench.html` opens with four paragraphs, and nothing else above
the fold:

- *I want a curve*
- *I want a terminal*
- *I want a strand*
- *I want a sheet*

Each is a plain description of the decision, ending in exactly one link — the
page that starts it. The words "Euler curve", "hodograph", "fidelity" and "G1"
appear in none of them. A reader who has never seen the project should be able
to pick by intent.

The full index sits underneath, for anyone who already knows the vocabulary.

### 2. A manifest, not hand-written HTML

`workbench/manifest.json` is the only place a page is described:

```json
{
  "key": "generators", "file": "generators.html", "group": "curve",
  "title": "Generators",
  "purpose": "Four integers in, an integer curve out.",
  "inputs": "degree, the generator polynomials h, u, v, and a step 1/m",
  "outputs": "exact control points, the integer grid they need, the scale"
}
```

`scripts/hub.py` reads it and writes the hub. The cards cannot drift from the
pages, because **the thumbnail is the page's own first `<svg>`**, pulled out of
the file at build time. Text is authored; pictures are derived. That is the same
split the board uses in `scripts/board/`.

If a page draws nothing inline — because its drawing is built by JavaScript, or
its SVG is too large to embed — the card says `no inline drawing` rather than
showing a broken box. It is a prompt to give the page a static first figure,
not a bug in the hub.

### 3. A shared bar on every page

Every listed page gets one line across the top:

> ← all inputs · CURVE · **in** … · **out** …

So the branch is navigable in both directions: the hub sends you to a page, the
page sends you back, and the page states what it takes and returns without you
having to scroll.

The bar is **injected**, not authored, and guarded by marker comments:

```html
<!-- hub-bar --> … <!-- /hub-bar -->
```

A re-run replaces the block instead of stacking a second bar. That keeps the
edit in one file, at the cost described next.

## The one rule

**Run `scripts/hub.py` after any page generator.**

A generator rewrites its page from scratch, and the bar goes with it. Nothing
breaks — the page is still correct — but the bar disappears until the hub is
rebuilt. The order is:

```sh
.venv/bin/python scripts/generators.py     # or catenary, primal, spine_sheet…
.venv/bin/python scripts/hub.py            # hub + bars
```

If this becomes annoying, the fix is to have each generator call
`hub.inject()` for its own page at the end. That is a five-line change per
generator, and it would remove the ordering rule entirely.

## Adding a page

1. Write the generator, and make it write one `<svg>` before any JavaScript
   figure, so the card has a thumbnail.
2. Add one entry to `workbench/manifest.json`: `key`, `file`, `group`, `title`,
   `purpose`, `inputs`, `outputs`.
3. Run `scripts/hub.py`.

If the page belongs to a new kind of decision, add a group to `groups` and a
paragraph to `DECISIONS` in `scripts/hub.py`. The paragraph is the only prose in
the system that is not in the manifest, because it describes the *category*, not
a page.

## What this does not do

- It does not change any page's contents beyond the bar.
- It does not check that the manifest is complete: a page missing from
  `manifest.json` simply does not appear, with no warning.
- It does not test that the links resolve — `manifest.json` and the filesystem
  are trusted to agree, which is worth a test.
